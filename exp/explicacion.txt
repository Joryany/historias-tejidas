# 🌸 Vamos paso a paso con las 5 funciones

Voy a explicártelas en el orden en que se ejecutan, no en el orden en que aparecen en el archivo. Porque así se entiende mejor el flujo.

Pero antes, un repaso mínimo de 3 conceptos que aparecen en el código y que aún no hemos visto juntos.

---

## 🧩 Conceptos nuevos antes de empezar

### 1. `dataset` — leer los `data-` desde JS

Ya lo usaste en el catálogo con `boton.dataset.categoria`. Funciona igual aquí:

```html
<input data-precio="50000">
```

```js
elemento.dataset.precio   // "50000" (string)
```

**Ojo:** siempre devuelve un **string**, por eso hay que convertirlo con `Number()`.

### 2. `.find()` — encontrar UN elemento

Es parecido a `filter`, pero devuelve **el primer elemento que cumpla**, no un array.

```js
const producto = productos.find(function(p) { return p.id === "abeja"; });
// devuelve el producto abeja, o undefined si no existe
```

### 3. Template literal anidado

Cuando pones `${ ... }` dentro de un template string, dentro puede ir **cualquier expresión**, incluso operaciones con ternarios:

```js
const marcado = indexItem === 0 ? "checked" : "";
```

Eso se llama **operador ternario**. Se lee: *"si la condición es verdadera, devuelve lo primero; si no, lo segundo"*. Es un `if/else` en una línea.

---

# 🔄 El flujo completo (qué pasa, en orden)

Cuando el usuario abre `producto.html?id=abeja`:

1. Se carga `datos.js` → tienes la lista de 113 productos.
2. Se carga `funciones-personalizacion.js` → tienes las 5 funciones definidas.
3. Se carga `producto.js` → busca el producto y llama a `prepararModalPersonalizacion`.
4. `prepararModalPersonalizacion` llama a `construirModal` → el modal se llena de opciones.
5. El usuario **abre** el modal → `actualizarPrecioModal` calcula el precio inicial.
6. El usuario **cambia** una opción → `actualizarPrecioModal` recalcula el precio.

Y cada función hace su trabajo. Vamos una por una.

---

# 📘 Función 1 — `construirModal(producto)`

**¿Qué hace?**
Toma las opciones del producto y **genera todo el HTML del modal** con radios, títulos y labels. Sin esta función, el modal estaría vacío.

**Paso a paso:**

### Paso 1.1 — Agarrar los elementos del DOM

```js
const contenedorOpciones = document.querySelector("#opciones-modal");
const tituloModal = document.querySelector("#titulo-modal");
```

Busca el `<div id="opciones-modal">` (donde irán los radios) y el `<h2 id="titulo-modal">`.

### Paso 1.2 — Verificar si el producto tiene opciones

```js
if (producto.opciones.length === 0) {
    return false;
}
```

Si el producto **no se personaliza** (array vacío), la función **termina aquí** y devuelve `false`. El modal nunca se llena.

### Paso 1.3 — Poner el título

```js
tituloModal.textContent = "Personaliza tu " + producto.nombre;
```

Ejemplo: "Personaliza tu Abeja". Cambia el texto del `<h2>`.

### Paso 1.4 — Arrancar el HTML acumulado

```js
let html = "";
```

Una variable vacía donde vamos a **acumular** todo el HTML que iremos generando.

### Paso 1.5 — Recorrer cada grupo de opciones

```js
producto.opciones.forEach(function(grupo, indexGrupo) {
```

Aquí viene la parte importante. `producto.opciones` es un **array de grupos**. Cada elemento es un grupo (ej: "Personaje", "Color", "Tamaño"). El `forEach` recorre **uno por uno**.

- `grupo` → el grupo actual.
- `indexGrupo` → su **posición** en el array (0, 1, 2...). Lo usamos para darle un nombre único a los radios de cada grupo.

### Paso 1.6 — Abrir el HTML del grupo

```js
html += `<div class="grupo-modal">`;
html += `<h3>${grupo.nombre}</h3>`;
```

Añade al acumulador un `<div>` con el nombre del grupo como título.

Ejemplo: 
```html
<div class="grupo-modal">
    <h3>Personaje</h3>
```

### Paso 1.7 — Recorrer cada item del grupo

```js
grupo.items.forEach(function(item, indexItem) {
```

Ahora recorremos los **items del grupo actual**. Si el grupo es "Personaje", los items son "Finn", "Jake", "BMO", "Marceline".

### Paso 1.8 — Preparar los datos del item

```js
const marcado = indexItem === 0 ? "checked" : "";
const dataPrecio = item.precio !== undefined ? `data-precio="${item.precio}"` : "";
const dataMultiplicador = item.multiplicador !== undefined ? `data-multiplicador="${item.multiplicador}"` : "";
```

Tres variables que preparan **atributos HTML condicionales**:

- **`marcado`**: si es el **primer item** del grupo (`indexItem === 0`), lleva `checked` para que arranque seleccionado. Los demás van vacíos.
- **`dataPrecio`**: si el item tiene `precio`, genera `data-precio="50000"`. Si no, cadena vacía.
- **`dataMultiplicador`**: igual pero con `multiplicador`.

**¿Por qué `undefined`?** Porque en JavaScript, si una propiedad no existe, su valor es `undefined`. Ahí preguntamos: *"¿tiene esta propiedad?"*.

### Paso 1.9 — Construir el `<label>` + `<input>`

```js
html += `
    <label class="opcion-modal">
        <input 
            type="radio" 
            name="grupo-${indexGrupo}" 
            value="${item.value}"
            ${dataPrecio}
            ${dataMultiplicador}
            ${marcado}
        >
        ${item.nombre}
    </label>
`;
```

Esto es lo que genera el radio real. Puntos clave:

- **`type="radio"`** → es un radio.
- **`name="grupo-${indexGrupo}"`** → **todos los items del mismo grupo** comparten `name`. Eso los hace un solo grupo de selección. Y `indexGrupo` garantiza que **cada grupo** tenga su propio `name`.
- **`value="${item.value}"`** → el valor interno ("finn", "grande", etc.).
- **`${dataPrecio}` y `${dataMultiplicador}`** → se expanden como atributos si los tienen, o quedan vacíos.
- **`${marcado}`** → `checked` si es el primero.
- **`${item.nombre}`** → el texto visible ("Finn", "Grande (40 cm)", etc.).

### Paso 1.10 — Cerrar el grupo

```js
html += `</div>`;
```

Cierra el `<div class="grupo-modal">` que abriste.

### Paso 1.11 — Al salir del forEach, meter todo el HTML al DOM

```js
contenedorOpciones.innerHTML = html;
return true;
```

Reemplaza el contenido del `<div id="opciones-modal">` con **todo el HTML acumulado** y devuelve `true`.

# 📘 Función 2 — `leerSelecciones(producto)`

**¿Qué hace?**
Mira **qué radios están seleccionados** en este momento y devuelve un array con la info de cada selección.

**Paso a paso:**

### Paso 2.1 — Arrancar el array de selecciones

```js
const selecciones = [];
```

Aquí iremos guardando cada elección del usuario.

### Paso 2.2 — Recorrer los grupos

```js
producto.opciones.forEach(function(grupo, indexGrupo) {
```

Recorremos los grupos **otra vez**, pero esta vez para leer qué está marcado.

### Paso 2.3 — Encontrar el radio seleccionado del grupo

```js
const radioElegido = document.querySelector(`input[name="grupo-${indexGrupo}"]:checked`);
```

Busca en el DOM **el radio marcado** del grupo actual. Usa el mismo `name` que pusimos al construir el modal.

**Pista clave:** `:checked` es el pseudo-selector que vimos antes. Devuelve el radio marcado, o `null` si ninguno lo está.

### Paso 2.4 — Si hay radio elegido, guardarlo

```js
if (radioElegido) {
    selecciones.push({
        value: radioElegido.value,
        precio: radioElegido.dataset.precio ? Number(radioElegido.dataset.precio) : undefined,
        multiplicador: radioElegido.dataset.multiplicador ? Number(radioElegido.dataset.multiplicador) : undefined
    });
}
```

- **`if (radioElegido)`** → si existe (no es `null`).
- **`.push(...)`** → agrega un objeto al array de selecciones.
- **`radioElegido.value`** → el value del radio ("finn", "grande").
- **`radioElegido.dataset.precio`** → lee el `data-precio` del HTML (string, ej: "50000").
- **`Number(...)`** → lo convierte a número.
- **`: undefined`** → si el radio no tiene ese `data-`, guarda `undefined` en lugar de un valor falso.

**Resultado:** un array tipo:
```js
[
    { value: "finn", precio: undefined, multiplicador: undefined },
    { value: "grande", precio: undefined, multiplicador: 1.5 }
]
```

### Paso 2.5 — Devolver

```js
return selecciones;
```

Devuelve el array. Lo usará la siguiente función.

# 📘 Función 3 — `calcularPrecio(producto, selecciones)`

**¿Qué hace?**
Toma el producto, toma las selecciones, y calcula el precio final aplicando las reglas.

**Paso a paso:**

### Paso 3.1 — Arrancar con el precio base

```js
let precio = producto.precio;
```

Usa `let` porque va a cambiar.

### Paso 3.2 — Primera pasada: buscar items con "precio" propio

```js
selecciones.forEach(function(seleccion) {
    if (seleccion.precio !== undefined) {
        precio = seleccion.precio;
    }
});
```

Recorre las selecciones. Si alguna tiene **precio propio** (como "Los dos juntos" → 85000), **reemplaza** el precio base.

**¿Por qué `let` y no sumar?** Porque el `precio` del item **reemplaza**, no suma. En el ejemplo: en vez de partir de 85000, partimos de 50000 si el usuario elige "Solo Chimuelo".

### Paso 3.3 — Segunda pasada: aplicar multiplicadores

```js
selecciones.forEach(function(seleccion) {
    if (seleccion.multiplicador !== undefined) {
        precio = precio * seleccion.multiplicador;
    }
});
```

Ahora recorre **otra vez**. Si una selección tiene multiplicador (ej: "Grande" ×2.10), **multiplica** el precio por él.

**¿Por qué dos pasadas y no una?** Porque el orden importa:
- Si primero multiplicamos y luego reemplazamos con un precio propio, perdemos la multiplicación.
- Si primero reemplazamos y luego multiplicamos, todo funciona.

Ejemplo: `precioFinal = 50000 × 2.10 = 105000`. Correcto.

### Paso 3.4 — Redondear

```js
return Math.ceil(precio / 100) * 100;
```

Ya lo conoces: redondea hacia arriba al múltiplo de 100. Devuelve el precio final limpio.

---

# 📘 Función 4 — `actualizarPrecioModal(producto)`

**¿Qué hace?**
Es la que se llama **cada vez que el usuario cambia algo**. Calcula el precio y lo muestra en pantalla.

**Paso a paso:**

### Paso 4.1 — Agarrar el elemento donde se muestra el precio

```js
const precioModal = document.querySelector("#precio-modal");
```

Busca el `<p id="precio-modal">` del modal.

### Paso 4.2 — Leer qué eligió el usuario

```js
const selecciones = leerSelecciones(producto);
```

Llama a la función 2.

### Paso 4.3 — Calcular el precio

```js
const precioFinal = calcularPrecio(producto, selecciones);
```

Llama a la función 3.

### Paso 4.4 — Mostrarlo

```js
precioModal.textContent = "Precio: $" + precioFinal.toLocaleString("es-CO") + " COP";
```

Pone el texto con formato.

### Paso 4.5 — Devolver el precio (opcional)

```js
return precioFinal;
```

Lo devuelve por si otra función (ej: "Agregar al carrito") lo necesita.

---

# 📘 Función 5 — `prepararModalPersonalizacion(producto, botonPersonalizar)`

**¿Qué hace?**
Es la función **orquestadora**. Prepara todo lo necesario **cuando la página carga**, antes de que el usuario abra el modal.

**Paso a paso:**

### Paso 5.1 — Si no hay opciones, esconder el botón

```js
if (producto.opciones.length === 0) {
    botonPersonalizar.style.display = "none";
    return;
}
```

Si el producto **no se personaliza** (Caso 0), **esconde el botón** "Personalizar". El usuario no lo ve. La función termina.

**¿Por qué?** Porque mostrar un botón que lleva a un modal vacío es raro. Mejor ocultarlo.

### Paso 5.2 — Construir el HTML del modal

```js
construirModal(producto);
```

Llama a la función 1. Llena el `<div id="opciones-modal">` con los radios.

### Paso 5.3 — Escuchar cambios en los radios

```js
const contenedorOpciones = document.querySelector("#opciones-modal");
contenedorOpciones.addEventListener("change", function() {
    actualizarPrecioModal(producto);
});
```

Escucha el evento **`change`** en el contenedor. Cuando el usuario cambie cualquier radio, se ejecuta `actualizarPrecioModal` y **el precio se recalcula solo**.

**Detalle bonito:** no necesitas escuchar cada radio individualmente. Escuchas el contenedor entero y dejas que el evento **suba** hasta él. Eso se llama **delegación de eventos**.

---

# 🎯 El resumen del flujo completo

Cuando el usuario abre un producto:

1. `prepararModalPersonalizacion` corre.
2. Esconde o muestra el botón.
3. Si hay opciones: `construirModal` genera el HTML.
4. Se prepara el `change` para recalcular.

Cuando el usuario abre el modal:
5. `actualizarPrecioModal` → lee + calcula + muestra.

Cuando el usuario cambia un radio:
6. El `change` dispara `actualizarPrecioModal` de nuevo.

Cuando el usuario cierra:
7. (Sin cambios, solo se oculta el modal).

---

# 🧠 El porqué de separar en 5 funciones

Podría ser **una sola función gigante**. Pero la partimos así:

- **`construirModal`** → hace UNA cosa: construir HTML.
- **`leerSelecciones`** → hace UNA cosa: leer qué eligió el usuario.
- **`calcularPrecio`** → hace UNA cosa: calcular.
- **`actualizarPrecioModal`** → hace UNA cosa: unir todo y mostrar.
- **`prepararModalPersonalizacion`** → hace UNA cosa: preparar al inicio.

**Cada función hace una cosa, y la hace bien.** Eso es lo que te permite cambiar una sin romper las otras. Ejemplo:

- Si mañana quieres cambiar la fórmula de precio → tocas `calcularPrecio` y nada más.
- Si mañana quieres cambiar el diseño del modal → tocas `construirModal` y nada más.
- Si mañana quieres guardar lo que el usuario eligió → tocas `leerSelecciones` y nada más.

Esto se llama **separación de responsabilidades**, y es exactamente lo mismo que te enseñé con `buscarProducto` hace unos días.

# 1️⃣ `datos.js` — El almacén de datos

## Su trabajo

**Guardar** información de los 113 productos. Nada más. No busca, no filtra, no muestra. Solo almacena.

## Su estructura

```js
const productos = [
    { /* producto 1 */ },
    { /* producto 2 */ },
    ...
];
```

- Es un **array** (`[ ]`).
- Cada elemento es un **objeto** (`{ }`).
- Todos tienen las mismas propiedades: `id`, `categoria`, `nombre`, `precio`, `imagen`, `alt`, `historia`, `materiales`, `etiqueta`, `opciones`.

## Cómo lo lee JavaScript

Cuando se carga en un HTML con `<script src="assets/js/datos.js"></script>`, JavaScript **crea una variable llamada `productos`** que contiene el array completo. Después de eso, cualquier otro script cargado en la misma página **puede usar `productos`** como cualquier variable.

## Por qué está separado

- **Reutilización:** el mismo archivo lo usan `catalogo.html` y `producto.html`. Sin él, tendrías que duplicar los 113 productos en ambos HTML.
- **Mantenimiento:** si cambias el precio de la Abeja, lo cambias en un solo lugar.
- **Futuro:** cuando migres a MongoDB, este archivo desaparece y su contenido se va a la base.

# 2️⃣ `catalogo.js` — El motor del catálogo

## Su trabajo

Generar **todas las tarjetas del catálogo dinámicamente** desde `datos.js`, y responder a las interacciones del usuario (filtrar, ordenar, buscar, paginar).

## Sus partes

### Parte A — Agarrar los elementos del DOM

```js
const contenedor = document.querySelector("#contenedor-productos");
const buscador = document.querySelector("#buscador");
const ordenador = document.querySelector("#ordenador");
const paginacion = document.querySelector("#paginacion");
const botonesCategoria = document.querySelectorAll(".boton-categoria");
```

Agarra todos los elementos que va a manipular. Sin esto, no puede hacer nada.

**Detalle importante:** `querySelectorAll` (con "All") devuelve **todos** los botones con esa clase, no solo el primero. Y como devuelve una lista, se puede recorrer con `forEach`.

---

### Parte B — El estado

```js
let estado = {
    busqueda: "",
    categoria: "todos",
    orden: "defecto",
    pagina: 1
};
```

**Qué es:** un objeto que dice **cómo se ve el catálogo ahora mismo**.

**Por qué existe:** cuando tienes varias cosas afectando lo que se muestra (búsqueda + categoría + orden + página), necesitas un solo lugar que guarde **todas** esas decisiones. Eso es el estado.

**Cómo funciona:** cada vez que el usuario hace algo (busca, filtra, ordena), cambias **una propiedad** del estado y vuelves a ejecutar `renderizar()`.

**La gran idea:** el estado es **la fuente de verdad**. No importa cómo se ve la pantalla — el estado dice cómo debería verse, y `renderizar()` se encarga de que coincidan.

---

### Parte C — La función `renderizar()`

Esta es la **función principal**. Hace todo el trabajo en 7 pasos:

```js
function renderizar() {
    // 1. Empezar con la lista completa
    let lista = productosBarajados;

    // 2. Filtrar por categoría
    if (estado.categoria !== "todos") {
        lista = lista.filter(p => p.categoria === estado.categoria);
    }

    // 3. Filtrar por búsqueda
    if (estado.busqueda !== "") {
        lista = lista.filter(p => p.nombre.toLowerCase().includes(estado.busqueda));
    }

    // 4. Ordenar
    if (estado.orden === "precio-menor") {
        lista = [...lista].sort((a, b) => a.precio - b.precio);
    } else if (estado.orden === "precio-mayor") {
        lista = [...lista].sort((a, b) => b.precio - a.precio);
    } else if (estado.orden === "alfabetico") {
        lista = [...lista].sort((a, b) => a.nombre.localeCompare(b.nombre));
    }

    // 5. Paginar
    const totalPaginas = Math.ceil(lista.length / POR_PAGINA);
    const inicio = (estado.pagina - 1) * POR_PAGINA;
    const fin = inicio + POR_PAGINA;
    const paginaActual = lista.slice(inicio, fin);

    // 6. Mostrar las tarjetas
    mostrarProductos(paginaActual);

    // 7. Mostrar los botones de paginación
    mostrarPaginacion(totalPaginas);
}
```

**Paso a paso:**

1. Empieza con la lista completa (barajada).
2. Si hay categoría seleccionada, filtra.
3. Si hay búsqueda, filtra otra vez.
4. Si hay orden, ordena.
5. Calcula qué 9 productos mostrar según la página actual.
6. Llama a `mostrarProductos` con esos 9.
7. Llama a `mostrarPaginacion` para dibujar los botones.

**La clave:** cada paso **reduce o reordena** la lista, y al final se muestra. Si cambia el estado, `renderizar()` se vuelve a ejecutar entero.

---

### Parte D — La función `mostrarProductos(lista)`

```js
function mostrarProductos(lista) {
    let html = "";
    lista.forEach(function(producto) {
        html += `
            <article class="tarjeta">
                <img src="${producto.imagen}" alt="${producto.alt}">
                ...
            </article>
        `;
    });
    contenedor.innerHTML = html;
}
```

**Qué hace:** recibe una lista de productos, construye el HTML de las tarjetas y lo mete en el contenedor.

**Por qué recibe una `lista`:** así es reutilizable. Sirve para mostrar todos, o solo los filtrados. La función **no sabe** qué lista le van a dar. Solo la dibuja.

**El truco:** acumula todo el HTML en una variable y asigna `innerHTML` **una sola vez**. Si lo hiciera producto por producto, el navegador reconstruiría el contenedor 9 veces. Menos eficiente.

---

### Parte E — La función `mostrarPaginacion(totalPaginas)`

```js
function mostrarPaginacion(totalPaginas) {
    let html = "";
    for (let i = 1; i <= totalPaginas; i++) {
        html += `<button class="boton-pagina" data-pagina="${i}">${i}</button>`;
    }
    paginacion.innerHTML = html;
    
    // Vuelve a escuchar los clicks en los botones nuevos
    const botonesPagina = document.querySelectorAll(".boton-pagina");
    botonesPagina.forEach(function(boton) {
        boton.addEventListener("click", function() {
            estado.pagina = Number(boton.dataset.pagina);
            renderizar();
        });
    });
}
```

**Qué hace:** genera un botón por cada página.

**Detalle importante:** cada vez que se re-renderiza la paginación, los botones se **recrean**. Los viejos desaparecen y aparecen nuevos. Por eso hay que **volver a añadir el `addEventListener`** a los nuevos. Si no, no responderían al clic.

**Por qué `Number(...)`:** `dataset.pagina` viene como string ("3"), y `estado.pagina` debe ser número. `Number()` lo convierte.

---

### Parte F — Los eventos

```js
buscador.addEventListener("input", function() {
    estado.busqueda = buscador.value.trim().toLowerCase();
    estado.pagina = 1;
    renderizar();
});

ordenador.addEventListener("change", function() {
    estado.orden = ordenador.value;
    estado.pagina = 1;
    renderizar();
});

botonesCategoria.forEach(function(boton) {
    boton.addEventListener("click", function() {
        estado.categoria = boton.dataset.categoria;
        estado.pagina = 1;
        renderizar();
    });
});
```

**Qué hace cada uno:**
- **Buscador:** cada vez que el usuario escribe (evento `"input"`), actualiza `estado.busqueda` y re-renderiza.
- **Ordenador:** cada vez que cambia la opción (evento `"change"`), actualiza `estado.orden`.
- **Botones de categoría:** cada vez que hace clic, actualiza `estado.categoria`.

**Detalle común a los tres:** cada uno **resetea `estado.pagina = 1`**. ¿Por qué? Porque si estás en la página 3 y de pronto buscas algo, quedarte en la página 3 con resultados nuevos no tiene sentido. Vuelves al inicio.

**Patrón:** evento → actualizar estado → re-renderizar. **Siempre el mismo patrón.** Eso es lo que hace robusto el sistema.

---

### Parte G — El arranque

```js
renderizar();
```

Esta línea, al final, ejecuta todo por primera vez. Sin ella, la página cargaría vacía y no pasaría nada hasta que el usuario tocara algo.

# 3️⃣ `producto.js` — El motor de la página de producto

## Su trabajo

Leer el ID de la URL, buscar el producto, y rellenar la página con su info.

## Sus partes

function buscarId(id) {
    for (let i = 0; i < productos.length; i++) {
        if (productos[i].id === id) {
            return productos[i];
        }
    }
    return null;
}

# 4️⃣ `funciones-personalizacion.js` — El motor del modal

## Su trabajo

Todo lo relacionado con la personalización: construir el modal, leer selecciones, calcular precio.

## Sus 5 funciones (ya explicadas, resumen)

| Función | Rol |
|---|---|
| `construirModal(producto)` | Genera el HTML de los radios según las opciones del producto |
| `leerSelecciones(producto)` | Lee qué opciones eligió el usuario |
| `calcularPrecio(producto, selecciones)` | Calcula el precio final |
| `actualizarPrecioModal(producto)` | Une todo: lee, calcula, muestra |
| `prepararModalPersonalizacion(producto, boton)` | Orquesta: esconde el botón si no hay opciones, construye el modal, prepara el `change` |

**Por qué está separado:** porque estas funciones son específicas del modal. Si las mezclas con `producto.js`, ese archivo se vuelve enorme. Separándolas, cada archivo hace lo suyo.
